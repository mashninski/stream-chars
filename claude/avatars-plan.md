ЭТАП A. Облако с сообщением и общий путь действий

A1. Общий путь действий (спека «Действия и источники»): программа шлёт оверлею одно событие действия `{ type: 'act', id, action, text? }`; `action` — имя из REACTIONS (public/js/actor.js). В src/viewers.js — метод вида `act(id, action, text)`, его вызывают все источники (тестовая панель, админ-панель, Twitch). Какое действие у какого источника — в config.json (`triggers`, например `"message": "jump"`), не в коде. Незнакомое оверлею действие — пропустить, строка в консоли браузера. Событие `message` заменить на `act` или оставить обёрткой — реши сам, причину в журнал.
A2. Облако (дополнение автора): сообщение → над персонажем облако с текстом, одновременно с прыжком. Шрифт некрупный (~16 px, config.json); текст целиком до `bubble.maxChars` (по умолчанию 100), длиннее — обрезать по слову и «…»; перенос по словам, ширина до `bubble.maxWidth` (280 px), не больше `bubble.maxLines` (4) строк; висит `bubble.minSeconds + bubble.secondsPerChar × длина` (2 + 0,05, не больше `bubble.maxSeconds` = 8). Новое сообщение того же зрителя заменяет облако. Облако показывается, даже если прыжок невозможен (падает, уходит). Сообщения, начинающиеся с `!`, облака не дают. Облака рисуются отдельным проходом поверх всех персонажей, программно, текст — только через canvas (fillText), не через HTML. Логика (обрезка, перенос по ширине через переданную функцию измерения, время) — в actor.js (например `actor.say(text)`), рисование — в render.js; разделение логики и рисования сохранить. Смайлы — текстом.
A3. Тестовая панель: поле текста сообщения рядом с «Паведамленне» (пусто — «тэставае паведамленне»).
A4. Настройки — в config.json, описание — в README.md («Настройки»).
