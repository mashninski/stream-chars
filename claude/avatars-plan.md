## Промпт задачи 1

```
Задача 1 направления «аватары зрителей»: каркас программы и оверлея.

Прочитай: CLAUDE.md, claude/README.md, верхнюю запись claude/journal.md, claude/avatars-spec.md, claude/avatars-plan.md. Автор — новичок: каждое действие, которое он делает сам, объясняй простыми словами.

Сделай:
1. Проверь, что установлен Node.js (`node -v`, `npm -v`). Нет или версия ниже 20 — остановись и дай автору пошаговую инструкцию установки LTS с nodejs.org под Windows; дальше не иди.
2. Заведи Node.js-проект в корне папки: `package.json`, запуск командой `npm start`. Код — JavaScript без сборки (без TypeScript, без бандлера). Зависимости — минимум: `ws` для WebSocket; HTTP-сервер — встроенный `node:http`, без фреймворков.
3. Настройки — в `config.json` (порт, размеры полосы, скорость ходьбы, лимит персонажей на экране). Значения по умолчанию — из спеки.
4. `.gitignore`: добавь `node_modules/` и `data/`. Существующие строки не трогай.
5. Сервер отдаёт:
   - `/overlay` — страница для OBS Browser Source 1920×1080, прозрачный фон, рисование на `<canvas>` без сглаживания;
   - `/test` — тестовая панель: поле ника + кнопки «добавить зрителя», «убрать зрителя», «сообщение», список текущих зрителей;
   - WebSocket, по которому сервер шлёт оверлею события `join`, `leave`, `message`.
6. Оверлей: на `join` появляется фигурка (цветной прямоугольник-заглушка, цвет от ника), над ней ник зрителя как есть. Фигурка ходит влево-вправо по нижней полосе на случайное расстояние и стоит случайную паузу, по очереди. На `leave` уходит за ближайший край. На `message` пока ничего (будет в задаче 3). Если оверлей перезагрузили — он получает от сервера текущий список и восстанавливает фигурки.
7. Логика состояний (ходит/стоит/уходит) — отдельный модуль, чтобы в задаче 2 подменить рисование прямоугольника на спрайт без переписывания логики.
8. Короткий `README.md` в корне: как запустить (`npm install`, `npm start`), какие адреса открыть. Существующую строку заголовка сохрани.

Не делай: Twitch, спрайты, способы появления, рейд, хранение — это задачи 2–5.

Проверка (обязательна, сам):
- `npm install` и `npm start` проходят без ошибок;
- запросы к `/overlay` и `/test` отдают страницы (например, `curl`);
- через WebSocket-клиент или тестовую панель отправь join/leave и убедись по логу сервера, что события доходят.
Остановить сервер после проверки.

Автору дай инструкцию: как запустить программу, открыть `/test` в браузере, добавить в OBS Browser Source (URL, 1920×1080), добавить трёх зрителей и посмотреть, что они ходят. Что прислать, если не работает: скриншот OBS и текст из окна терминала.

Закрытие задачи (по CLAUDE.md):
- сверь сделанное с этим промптом и со спекой; требование спеки, которое не покрыла ни одна задача плана, — в claude/open-questions.md;
- решения с причинами — в claude/journal.md (новая запись сверху, перечитай файл перед записью);
- в claude/avatars-plan.md: статус задачи 1 → «сделано», фактические часы автора, промпт задачи 2 одним блоком по образцу этого;
- коммит па-беларуску `аватары: каркас праграмы і аверлэя`, потом `git show --stat HEAD` — изменились ровно твои файлы; push только если всё сошлось;
- последним — «дальше дешевле в новом чате» и готовый блок для него.
```

## Промпт задачи 2

```
Задача 2 направления «аватары зрителей»: спрайты, каталог персонажей, закрепление зритель → персонаж.

Прочитай: CLAUDE.md, claude/README.md, верхние записи claude/journal.md (от «Каркас задачи 1»), claude/open-questions.md, claude/avatars-spec.md (разделы «Как зритель получает персонажа» и «Графика»), claude/avatars-plan.md. Код задачи 1: src/server.js, src/viewers.js, public/js/*.js, config.json. Автор — новичок: каждое действие, которое он делает сам, объясняй простыми словами.

Шаг 0. Спроси автора, сколько времени у него заняла задача 1 (запуск, проверка в OBS) и заработало ли в OBS. Не заработало — сначала чини это, задачу 2 не начинай. Ответ — в таблицу часов claude/avatars-plan.md.

Сделай:
1. Формат персонажа — как в спеке: папка `characters/<імя>/` с `sheet.png` (кадры в ряд, анимации строками) и `character.json` (размер кадра; для каждой анимации — строка, число кадров, скорость в кадрах/с). Обязательные анимации: `idle`, `walk`, `jump`, `fall`, `land`, `shake`, `parachute`. Кадры смотрят вправо, влево — зеркало при рисовании. Кадр по умолчанию 32×32, увеличение — `overlay.scale` из config.json, без сглаживания.
2. 6 персонажей-заглушек с именами па-беларуску (имя = имя папки = то, что зритель напишет в `!перс`; короткие, без пробелов). Различаются цветом и шапкой. `sheet.png` делает скрипт в `scripts/` на встроенных модулях Node (`node:zlib` для PNG), без новых зависимостей; PNG коммитятся, скрипт — тоже (перерисовать заглушки). Анимации простые, но различимые: ходьба — хотя бы 2 кадра, прыжок, парашют — с куполом.
3. Каталог: программа при запуске читает `characters/`, проверяет каждый `character.json` (все обязательные анимации есть, строки в пределах `sheet.png`); битый персонаж — понятное сообщение в терминале па-беларуску и пропуск, программа не падает. Сервер отдаёт `/characters/<імя>/sheet.png` (имя кириллицей — учесть кодирование URL; отдавать только файлы из `characters/`).
4. Закрепление: зритель без персонажа получает дизайн, который сейчас реже всего используется среди закреплённых (равенство — случайно). Хранение — `data/viewers.json` по id зрителя (сейчас id = ник в нижнем регистре, в задаче 4 станет user_id Twitch): персонаж + последний ник. Папку `data/` создать, если нет; запись — через временный файл и переименование, чтобы при сбое файл не бился. Персонаж из файла исчез из каталога — выдать новый.
5. Смена персонажа: функция в src/viewers.js (или рядом), вызываемая тестовой панелью сейчас и командой `!перс` в задаче 5. Неверное имя — ничего не происходит, строка в терминале. Персонаж на экране меняется сразу (новое событие по WebSocket).
6. События: `join` и `state` несут имя персонажа; оверлей получает каталог (размеры кадров, анимации) в `state`.
7. Оверлей: public/js/render.js рисует спрайт вместо прямоугольника: состояние `idle` → анимация `idle`, `walk` и `leave` → `walk`; кадр — от `actor.stateTime`. Ник над головой — как сейчас. public/js/actor.js (логика) не переписывать; если нужно поле — добавить, не меняя поведение.
8. Тестовая панель: у каждого зрителя в списке видно имя его персонажа; выпадающий список персонажей + кнопка «Змяніць персанажа» для ника из поля.
9. README.md в корне: раздел «Свои персонажи» — как заменить заглушку своей графикой (какие файлы, какой формат), без правки кода.

Не делай: способы появления, прыжок на сообщение, рейд, лимит и очередь (задача 3), Twitch (задачи 4–5).

Проверка (обязательна, сам):
- `npm start` без ошибок, в терминале — список загруженных персонажей;
- `curl` отдаёт `sheet.png` персонажа с кириллическим именем;
- через WebSocket-клиент или панель добавь 6 зрителей — у всех разные персонажи; добавь 7-го — получает один из использованных; `data/viewers.json` заполнен;
- перезапусти программу, добавь тех же зрителей — персонажи те же;
- смена персонажа через панель доходит до оверлея (лог сервера + скриншот в браузерной панели);
- испорти копию `character.json` во временной папке персонажа — программа пишет ошибку и работает дальше; временную папку удали.
Остановить сервер после проверки.

Автору дай инструкцию: запустить, открыть `/test`, добавить 6 зрителей, посмотреть в OBS, что персонажи разные и шагают; сменить одному персонажа; закрыть программу, запустить снова, добавить тех же — персонажи сохранились. Что прислать, если не работает: скриншот OBS и текст из окна терминала.

Закрытие задачи (по CLAUDE.md):
- сверь сделанное с этим промптом и со спекой; требование спеки, которое не покрыла ни одна задача плана, — в claude/open-questions.md;
- решения с причинами — в claude/journal.md (новая запись сверху, перечитай файл перед записью);
- заглушки из claude/open-questions.md, которые закрыла эта задача, — убрать оттуда, причину в журнал;
- в claude/avatars-plan.md: статус задачи 2 → «сделано», фактические часы автора, промпт задачи 3 одним блоком по образцу этого; в промпт задачи 3 внести пункты из claude/open-questions.md, помеченные «вписать в промпт задачи 3»;
- коммит па-беларуску `аватары: спрайты і замацаванне персанажаў`, потом `git show --stat HEAD` — изменились ровно твои файлы; push только если всё сошлось;
- последним — «дальше дешевле в новом чате» и готовый блок для него.
```
