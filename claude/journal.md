# Журнал решений

Свежие сверху. Задним числом не переписывается. Правила — в `claude/README.md`.

## 27.09.2026

### Задача 4, этап F: админка — один WebSocket с ролями, команды с ответом, реестр команд
Клиент называет роль в адресе (`/ws?role=overlay|test|admin`). Менять данные могут только тестовая панель и админка; оверлей — только слушает. Команда админки — `{ type: 'admin', id, cmd }`, ответ — `admin-reply` с тем же `id` (ошибка — текстом па-беларуску). Модули Twitch и наград добавляют свои команды и строки «Стан» сами (`admin.command`, `admin.status`) — `src/admin.js` про них не знает. Отвергнуто: HTTP-запросы для команд — вторая дорога рядом с уже открытым WebSocket и своя проверка Origin.

### Задача 4, этап F: окна — разделы `<details>`, окно «Персанажы» — виртуальный список
Сворачивание — родное `<details>`, открытые разделы — в `localStorage` каждой док-панели. «Персанажы» рисуют только видимые строки (проверено на 300 зрителях); столбцы — из реестра признаков. Перерисовка по событиям — таймером, не `requestAnimationFrame`: в свёрнутом окне кадры не идут, и строка оставалась со старыми кнопками (нашлось на проверке). Отвергнуто: библиотека таблиц — внешние зависимости запрещены и не нужны.

### Задача 4, этап F: награды — записи в `config.json`, админка правит название, цену, вкл/выкл
Список по умолчанию — `claude/heroes-spec.md` + три общих действия (цены 500/800/600 — предложение, у автора в `claude/open-questions.md`). Новая награда — запись в `rewards`; действие — строка общего пути (`reroll:<признак>`, `special`, `<сцена>`). Запасной режим (`rewardMode: manual`) — связь «название → действие» в `rewardLinks`. Описание награды «убор» — «Толькі для падпісчыкаў канала» (как в промпте задачи); в Twitch по-белорусски «падпісчык» обычно и значит фолловер — сверить с автором.

### Задача 4, этап E: скрипт OBS проверен в LuaJIT из самого OBS, но без OBS
Отдельный Lua не ставился. Скрипт загружен в `lua51.dll` из папки OBS (тот же LuaJIT, что внутри OBS) через Python ctypes, API `obslua` подменён, проект — копия во временной папке. Проверено: синтаксис; запуск программы скрытым процессом (`CreateProcessW` + `CREATE_NO_WINDOW`) с `--parent-pid`; повторный запуск — «уже работает»; «Перазапусціць праграму»; `script_unload` → файл `stop` → программа вышла; процесс-родитель закрылся → программа вышла сама. **Не проверено** (нужен настоящий OBS): «Дадаць аверлэй у сцэну», «Абнавіць аверлэй» (кнопка `refreshnocache` источника), вид окна свойств, порядок вызова функций скрипта самим OBS — первым шагом задачи 5. Отвергнуто: `os.execute`/`io.popen` — открывают окно терминала; `io.open` для файлов — не открывает пути с кириллицей (файлы — через `CreateFileW`).

### Задача 4, этап E: занятый порт при запуске — две повторные попытки через 6 с
Программа при занятом порте выходит с кодом 0 (так задумано для второго экземпляра). Но если OBS перезапустили быстро, старая программа ещё не заметила, что OBS закрылся (проверка раз в 5 с), и новая вышла бы — а потом вышла бы и старая: программы нет. Скрипт видит быстрый выход с кодом 0 и пробует ещё раз через 6 с, не больше двух раз. Отвергнуто: проверять порт из Lua — в LuaJIT нет сокетов без лишнего кода WinSock.

### Задача 4, этап D: сцены — генераторы (`function*`), ожидания через `yield`
Сценарий пишет шаги подряд, `yield` ждёт секунды, движение, анимацию или условие с пределом; параллельное — `yield [a, b]`. Движок (`public/js/scene-engine.js`) без браузера: все 23 сцены прогнаны в Node до конца. Программа импортирует файлы сцен ради `meta` (название, вес, случаи) — список и веса берутся из самих файлов. Отвергнуто: шаги сцены списком в JSON — условия («первый подошедший», «пока не добежал») превратили бы данные в язык программирования; колбэки и таймеры — сцену на 15 шагов не прочитать.

### Задача 4, этап D: реакции соседей — состояния героя (`AFFECTS` в `actor.js`), не часть сцены
Цель отпускается из сцены и реагирует сама: паника, отброс, сон, пьяный сон, трёт глаза, хлопает по карманам, злость, злость с паникой, выпивка, драка, пьяный. Поэтому минутный сон после «Напаіць» не держит сцену и её место в лимите одновременных. Маг после «Віна» уходит в пьяный сон так же. Длительности — `reactions` в `config.json`. Уход во время реакции ждёт её конца, но не дольше `scenes.leaveWaitSeconds`.

### Задача 4, этап D: одинаковость в двух оверлеях — зерно и порядок по id; «ближайший» может различаться
Случайные цели и случаи выбираются генератором по зерну от программы, кандидаты — в порядке id. «Ближайший» и «в радиусе» зависят от того, где кто стоит, а ходят герои в каждом оверлее по-своему — там цели могут различаться. Отвергнуто: синхронизировать позиции через программу — на каждый шаг каждого героя сообщение по сети ради редкого случая двух оверлеев.

### Задача 4, этап D: очередь купленных действий — в программе, а не в оверлее
`viewers.act(…, { wait: true })`: зритель не на экране (в очереди или офлайн) — действие ждёт его появления до конца работы программы, потом уходит оверлею сразу за появлением; оверлей сыграет, когда герой встанет на землю и освободится. Сообщения из чата не ждут (не на экране — ничего). Отвергнуто: очередь в оверлее — перезагрузка оверлея стёрла бы оплаченное.

### Задача 4, этап D: «первое слово» — флаг и ник пишет программа, показывает сцена
Первое сообщение (не команда) от зрителя на экране: `flags.firstWord` и `nameShown` сразу в `data/viewers.json`, оверлею — сцена `common/first-word` (`ownsText`: облако рисует сама сцена и держит его, пока герой думает). Отдельного сообщения «ник виден» оверлею нет — иначе ник появился бы раньше, чем выплывет из облака. Команда `!…` первым словом не считается.

### Задача 4, этап D: сцена смены выгляда — одна на все смены (`triggers.change`)
Новый убор за фолловинг, смена класса, пола, цвета, убора за баллы и из админки — «пух» и радость (`common/change`). Отвергнуто: своя сцена на каждый признак — одинаковые файлы.

### Задача 4, этап D: общие действия — «Памахаць», «Патанцаваць», «Сесці адпачыць»
Предложение исполнителя; файлы `public/js/scenes/common/`. Автор утверждает список и цены (`claude/open-questions.md`). Костёр пастуха — простая сцена (разжёг, пожарил, съел), подробности — у автора.

### Задача 4, этап C: каталог героев — папка `heroes/`, id латиницей, `info.json` у всех предметов
Структура и формат — `README.md` («Свая графіка»). Категория — любая папка `heroes/<категория>/`, предмет — папка с `info.json`: с `layers` — слои на общей сетке тела (класс), с `image` — свой лист (убор, крылья, реквизит, существо). Один загрузчик на все категории: новая категория (плащи, питомцы) — папка и запись в реестре, код не трогается. id папок — латиницей (`warrior`), название для людей — `title` (`Ваяр`). Причина: id попадают в адреса картинок, имена файлов сцен, ключи настроек и скрипт OBS; кириллица в них — лишнее кодирование и риск. Правило «имя папки = имя для `!перс`» ушло вместе с командой. Отвергнуто: кириллические папки, как у старых заглушек; отдельный формат описания на каждую категорию.

### Задача 4, этап C: реестр признаков — `heroes/traits.json`, стратегии выбора — в коде
Запись признака: тип значения (`item`/`choice`/`color`/`bool`), когда появляется (`appears`), как выбирается (`pick`: веса, дальний цвет, ступени), меняется ли из админки и за баллы, слой рисования. Код знает конечный набор типов, событий и способов выбора; новый признак из этого набора — одна запись. Крылья — признак со ступенями из настроек (`tiers.wings`), а не вычисление на лету: админка может поставить крылья руками. Отвергнуто: реестр в коде — «без хардкода» нарушено; произвольные формулы в JSON — язык программирования в данных.

### Задача 4, этап C: слои класса — три листа на пол (`body`, `jacket`, `decor`), точки привязки по кадрам в `body.json`
Тело с головой и причёской, маска куртки, украшения класса — отдельные листы на общей сетке; убор, крылья, предмет в руке — по точкам кадра (`head`, `back`, `handR`, `handL`, у лежачих поз — с поворотом). Зеркало влево — одно преобразование на все слои. Окрашенная куртка кэшируется по паре «лист + цвет». Серый 178 = ровно цвет героя, темнее — тень, светлее — к белому. Отвергнуто: один лист с телом и курткой — куртку не выделить для окраски; лежачие позы без поворота убора — корона висела бы в воздухе.

### Задача 4, этап C: хранилище v2 и перенос старых записей
Формат — `src/store.js`. Старый файл (поле `character`) читается и переводится в память; старым записям — новые случайные признаки (старые персонажи — не классы). Копия старого файла `viewers.v1-<время>.json` пишется перед первой записью (флаг `wx` — не перезаписать), старый файл не удаляется. Проверено на копии `data/viewers.json` во временной папке: 18 записей перенесены, копия побайтно равна старому файлу. `data/` автора не трогалась.

### Задача 4, этап C: цвет ника по умолчанию — палитра из 15 цветов Twitch по хэшу ника
Twitch отдаёт пустой цвет, если зритель не выбирал; какой цвет у него в чате, Twitch не сообщает (`claude/heroes-spec.md`). Программа берёт цвет из стандартной палитры по нику — устойчиво, но может не совпасть с тем, что видит чат. Отвергнуто: белый у всех — ники неразличимы.

### Задача 4, этап C: импорт графики — `scripts/import-art.js`, один масштаб на все клетки
Все клетки листа уменьшаются одним масштабом (по самой крупной позе), иначе лежачий персонаж стал бы размером со стоящего. Ноги — на нижнюю строку, середина — по рамке персонажа. Куртка — «серые» пиксели (малая разница каналов, яркость около `--jacket`) уходят в маску. Проверка — `--selftest` (рисует сетку с шумом, линиями сетки и мягким краем, импортирует, проверяет). Отвергнуто: «большинство цветов» вместо ближайшего соседа — просили ближайшего соседа; можно добавить, если на Г1 кадры будут шумными.

### Задача 4, этап B: настройки поверх `config.json`, проверка по образцу значений по умолчанию
`data/settings.json` хранит только изменённое. Ключ должен быть в `config.json`, тип — тот же; пары «от–до» — по порядку; числа — от 0, особые границы — таблица `LIMITS` в `src/settings.js`. Новая настройка в `config.json` проверяется сама. Разделы с ключами пользователя (`weights`, `rewardLinks`) — отдельный список. Неверная строка в файле при запуске пропускается по одной, остальное применяется. Отвергнуто: схема на каждую настройку — вторая копия `config.json`; отказ от всего файла из-за одной ошибки.

### Задача 4, этап B: остановка — `--parent-pid`, файл `stop`, второй экземпляр выходит тихо
Старый `stop` удаляется только после того, как порт занят: если порт свободен, прошлая программа уже вышла и сигнал ничей; если занят — второй экземпляр выходит, не трогая чужой сигнал. Отвергнуто: удалять `stop` при запуске — «Перезапустить» могло бы съесть сигнал, адресованный старой программе.

### Задача 4, этап A: облако — логика и перенос в `actor.js`, рисование отдельным проходом
Перенос строк — чистая функция с измерителем ширины (в оверлее — `measureText`, в проверке — подмена), поэтому проверяется в Node. Облако не зависит от состояния героя: показывается в падении, уходе, сцене. Отвергнуто: перенос в `render.js` — без браузера не проверить.

### Заведено направление «герои» (`claude/heroes-spec.md`, `claude/heroes-plan.md`)
Автор описал новую модель персонажа: класс, пол, цвет куртки, головной убор за фолловинг, крылья за подписку, спецдействия классов со взаимодействием соседей, награды за баллы, админку с окнами, свою графику через Nano Banana 2. Это новая система, а не правка v1, поэтому своя спека; `claude/avatars-spec.md` ссылается на неё там, где старое заменено («Как зритель получает персонажа», «Графика», награды, админка). Код героев — в задаче 4 на заглушках, графика — шаги Г1–Г5 после задачи 5. Отвергнуто: дописать всё в avatars-spec — одна спека на две системы, решения перемешались бы.

### Команда `!перс` убрана (решение автора)
Смена класса теперь стоит 2000 баллов; бесплатная команда обесценила бы награду. Внешность меняется только баллами и из админки. Закрыт вопрос «как зритель узнаёт имена персонажей для `!перс`» — команды нет. Поэтому в именах классов теперь можно «і» и «ў» (правило «без і и ў» было ради набора команды).

### Плут — «Злодзей» (решение автора)
Отвергнуты «Махляр», «Шэльма».

### Куртка — маска, окрашиваемая программой, а не отдельные скины на каждый цвет
Автор оставил выбор исполнителю. Маска в оттенках серого, окраска с сохранением теней. Причина: цветов неограниченно много, алгоритм «дальний цвет» выбирает из непрерывного пространства; рисовать один раз. Отвергнуто: набор скинов разных цветов — ограниченная палитра и повтор рисования.

### Единое тело и точки привязки
Все классы и полы на одной сетке кадров, одни пропорции, точки привязки (голова, спина, руки). Причина: просьба автора «персонаж унифицирован, разные скины» — общие анимации, уборы и крылья рисуются один раз на всех. Отвергнуто: отдельный набор анимаций у каждого класса — ×12 работы на каждую общую анимацию.

### Класс при первом появлении — по весам редкости; заменяет «дизайн, который реже всего используется»
Причина: автор хочет редкие предметы и настраиваемые шансы; «реже всего используется» с весами несовместимо. По умолчанию веса равны.

### «Дальний цвет» — OKLab, максимум минимального расстояния до цветов на экране
Причина: просьба автора «чтобы пестрило, каждый не похож на соседа»; OKLab — расстояния близки к восприятию глаза. Цвет закрепляется и не пересчитывается. Отвергнуто: RGB/HSV-расстояния — соседние по числам цвета выглядят по-разному, и наоборот.

### Редкость — веса у каждого случайного выбора, окно в админке; флаг «только за баллы» отменён
Отменяет «персонажи только за баллы» из записи «Баллы канала — в задаче 5, заготовки — в задаче 4». Вес 0 делает то же и проще.

### Награды создаёт программа; отменяет «программа награды только читает»
Автор хотел бы, чтобы награды заводились сами. Twitch это позволяет (`channel:manage:redemptions`, до 50 наград на канал, только компаньонам и партнёрам); программа управляет только своими наградами и отмечает их выполненными. Баллы не возвращаются (решение автора). Запасной путь — ручные награды и связь «название → действие».

### Спецдействие за баллы — случайное своего класса по весам (решение автора)
Отвергнуты выбор номером в тексте награды и отдельная награда на каждое (лимит 50 кончился бы быстро).

### Сцены — файлы JS в папке сценариев, исполняются в оверлее по зерну программы
Причина: драки, засады, погони — это шаги с условиями; язык описаний в JSON пришлось бы превращать в язык программирования. Новый файл подхватывается сам — «без хардкода» соблюдён. Зерно от программы — два оверлея показывают одно и то же. Потраченное за баллы действие ждёт появления зрителя: баллы не возвращаются.

### Ник — после первого сообщения, цветом из чата Twitch; убор — после фолловинга; крылья — по месяцам подписки
Решения автора; как — `claude/heroes-spec.md` («Когда что видно», «Twitch: что ещё нужно»). Месяцы — из значка подписчика в сообщении чата: Twitch отдаёт их там без отдельного запроса. Подписка кончилась — крылья прячутся (вопрос автору в `claude/open-questions.md`).

### Админка: сворачиваемые разделы и окна «Персанажы», «Рэдкасць»; отменяет «разделы вкладками»

### Поведение — таблицами, новое добавляется записью (требование автора при запуске задачи 3)

Семь обязательных остались (на них держится поведение v1). Новые анимации необязательны: у состояния есть `fallback`, персонаж без новой анимации играет запасную. Причина: новое поведение не должно ломать старых персонажей и требовать перерисовки всего каталога.

### «Один раз или по кругу» — в `character.json` (`"loop": false`), а не в коде
Заглушка «все анимации по кругу» закрыта: `jump`, `land`, `shake` у заглушек помечены `"loop": false` и держат последний кадр. Без поля — по кругу. Приземление и отряхивание длятся одно проигрывание своей анимации (длину логика берёт из листа персонажа). Причина: это свойство анимации, художник решает его вместе с кадрами; список одноразовых в коде — тот самый хардкод. Отвергнуто: вывод из имени анимации.

### Способ появления выбирает программа, по весам из `config.json`
`src/viewers.js` выбирает (`entrances` — веса, в окне после рейда — `parachute`), оверлей исполняет; незнакомое оверлею имя — «пух». Способ пишется в терминал (`[join] … з'яўленне: …`). Причина: окно после рейда знает только программа; веса правятся без кода; лог — проверка без браузера. При восстановлении списка (перезагрузка оверлея) способа нет — персонаж просто стоит на месте. Отвергнуто: выбор в оверлее — не знает про рейд, и две вкладки оверлея выбрали бы разное.

### Прыжок — реакция поверх состояния
Идущий продолжает идти в прыжке, стоящий — стоять; анимация `jump` на время прыжка. Прыгает только стоящий на земле (не в падении, не в облачке, не уходящий); второе сообщение во время прыжка не перезапускает его. Причина: спека «подпрыгивает и продолжает»; перезапуск на каждом сообщении при спаме — дрожание. Уход во время падения или облачка откладывается до приземления, чтобы персонаж не уходил по воздуху.

### Рейдеры в лимит зрителей не входят; новый рейд уводит прошлых
Рейдеры — отдельно от `maxOnScreen`, своя граница `raid.maxCount`. Приходят как обычные `join` с `raider: true`, уходят обычным `leave` по таймеру программы — оверлей про рейд не знает. Причина: рейд — короткое главное событие, его нельзя урезать из-за полного экрана; а вытеснять настоящих зрителей в очередь безымянными — хуже. Отвергнуто: рейдеры в лимите (вытесняют зрителей); рейдеры только на свободные места (при полном экране рейда не видно). Потолок на экране — `maxOnScreen` + `raid.maxCount`; второй рейд, пока гуляет первый, уводит первых — рейдеров не больше `raid.maxCount`. Рейдеры не пишутся в `data/viewers.json`, дизайн — случайный из каталога.

### Очередь — на программе, оверлей о ней не знает
`src/viewers.js`: не больше `maxOnScreen` на экране, лишние — в очереди по порядку прихода; ушёл с экрана — выходит первый из очереди (со своим способом появления); ушёл из очереди — просто убирается. Персонаж закрепляется уже при постановке в очередь, `!перс` меняет его и в очереди. Тестовая панель показывает экран, очередь и рейд отдельно. Заглушка «`maxOnScreen` не применяется» закрыта.

### Появление — три способа; заглушка «сразу на случайном месте» закрыта
Из-за края, облачко (рисуется программно пиксельными кругами), падение → приземление → отряхивание; на парашюте — спуск → приземление. Скорости, высоты, длительности — `overlay.*` в `config.json`, значения выбраны исполнителем, правятся после просмотра в OBS.

### Имена заглушек — без «і» и «ў»
Шесть заглушек: кухар, рыцар, маг, пастух, турыст, марак (`characters/`). Причина: имя набирают в `!перс`, а на русской раскладке, которая у многих зрителей, нет «і» и «ў». Имя сравнивается без учёта регистра и способа записи букв (Unicode NFC) — `src/characters.js`.

Временный файл → fsync → переименование. Причина: при сбое остаётся целый старый или целый новый файл. Синхронно, потому что записей мало, а очередь асинхронных записей — лишняя сложность. Причина: так в спеке; иначе постоянные зрители, пришедшие вместе, чаще получали бы одинаковых.

Причина: панель и сообщения программы — интерфейс продукта (правило языка в `CLAUDE.md`), комментарии — документация.

### `README.md` в корне переведён из UTF-16 в UTF-8
Причина: остальные файлы в UTF-8; смешение кодировок ломает кириллицу в редакторах и на GitHub. Заголовок сохранён.

### Заведено направление «аватары зрителей» (`claude/avatars-spec.md`, `claude/avatars-plan.md`)
Зачем: это сам продукт. Исходник — описание автора и черновое обсуждение с ChatGPT. Из обсуждения взяты требования автора, утверждения ИИ проверены отдельно.
Отвергнуто: готовый Stream Avatars (платный); Meld Pixel Art Chat Avatars (персонаж исчезает через ~5 мин без сообщений); варианты, где аватарка Twitch становится телом персонажа (автору не нравится). Готовые open-source проекты — только референсы.

### Присутствие = список чата Twitch, уход — после 3 пропущенных опросов
Причина: Twitch не отдаёт список зрителей, только залогиненных в чате (Get Chatters; проверено по dev.twitch.tv). IRC JOIN/PART тоже про чат и отключается при >1000 в чате. Запас в 3 опроса — список обновляется с задержкой.
Отвергнуто: «только написавшие в чат» (не будет молчунов). «Список + мгновенное появление по сообщению» автор не выбрал — вопрос в open-questions.

### Рейдеры — безымянные парашютисты
Причина: событие `channel.raid` содержит только канал-рейдер и число зрителей, ников нет (проверено по EventSub reference). Идея «собрать ники рейдеров» невыполнима.

### Персонаж выдаётся случайно, меняется командой `!перс`, хранится по user_id в JSON
Причина: выбор автора «случайно + смена». user_id, а не ник: ник можно сменить. JSON: зрителей мало, база данных не нужна.
Отвергнуто: только случайно (зритель не выбирает), только выбор (у большинства будет дефолтный), SQLite (избыточно для v1).

### Графика v1 — заглушки, формат спрайтов фиксируется сразу
Причина: механику можно проверить без готового арта. Фиксированный формат (`character.json` + `sheet.png`) позволяет заменить графику без правки кода. 32×32 — значение по умолчанию, меняется в `character.json`.

### Программа локальная (Node.js), оверлей — страница на localhost в OBS Browser Source
Причина: $0/мес, нет сервера, который нужно держать и защищать. Вход в Twitch — Device Code Flow: публичный клиент, client secret не нужен.
Отвергнуто: облачный сервис — деньги и сложность без выгоды для одного стримера.

### Токены Twitch — в `data/twitch-tokens.json`, не в `.env.local`
Причина: refresh token публичного клиента одноразовый, программа перезаписывает его при каждом обновлении; переписывать `.env.local` программой ненадёжно. `data/` в `.gitignore`. Client ID остаётся в `.env.local`.

### Объём v1: разные появления, рейд, реакция на сообщение
Вне v1: лазанье по аватарке, автобус при рейде, кастомизация — в `claude/ideas.md`. Причина: выбор автора.

### Оценка ChatGPT в «сессиях Codex и токенах» не перенесена
Причина: план требует $/мес и часы автора, сессии и токены на это не отвечают.

### Заведена система работы с Claude
Документация живёт в папке проекта (git), в проекте claude.ai — только правила (`claude/project-instructions.md`). Правила для Claude Code — `CLAUDE.md`, карта и правила ведения — `claude/README.md`.
Причина: решения, принятые в чатах, теряются вместе с чатами; два комплекта документов (в claude.ai и в папке) на прошлом проекте разошлись.
Система перенесена с проекта сайта, где проработала месяц.

### Работа идёт цепочкой чатов, профильного чата нет
Один чат — одна задача; закрывающий чат пишет журнал и промпт следующей задачи. Планировочный чат в claude.ai — только для нового направления или крупного разбора.
Причина: приоритет — экономия токенов; длинный чат оплачивает всю переписку в каждом запросе.
Отвергнуто: постоянный диспетчерский чат на каждую задачу (лишняя пара чатов на каждый шаг) и профильный чат (нет области со своим хозяином). Вернуться, если появится такая область — например, дизайн аватаров.

### Экономия токенов — без вреда результату
Правила экономии в `CLAUDE.md`. Не экономится: перечитывание файла перед записью, проверка сборки и `git show --stat`.
Причина: на сайте запись из старой копии трижды молча затирала чужие правки — это дороже любых сэкономленных токенов.
