# Журнал решений

Свежие сверху. Задним числом не переписывается. Правила — в `claude/README.md`.

## 27.09.2026

### Задача 4 — одна большая, три этапа (просьба автора)
Облако с сообщением, админ-панель и Twitch — одним промптом задачи 4 (`claude/avatars-plan.md`), этапы A → B → C, у каждого свой коммит и проверка; переписка длинная после этапа — остаток уходит в новый чат промптом «продолжение». Причина: автор просил одной задачей; этапы с коммитами сохраняют главное правило «один чат — одна задача» — сломанный этап не тянет за собой остальные. Отвергнуто: три отдельные задачи — против просьбы автора; одна задача без этапов — длинная переписка без точек сохранения.

### Облако с сообщением: целиком до 100 символов, не только при прыжке
«Целиком, но с лимитом» — текст целиком до `bubble.maxChars`, длиннее обрезается по слову с «…». Причина: сообщение Twitch до 500 символов закрыло бы полэкрана. Облако показывается и когда прыжок невозможен (падает, уходит): текст зрителя важнее прыжка. Команды `!…` облака не дают — это не реплика. Текст рисуется на canvas, не HTML: чужой текст не может стать разметкой. Значения — спека «Действия и источники».

### Действия и источники — одно событие `act`, связь источник → действие в конфиге
Ручка под баллы канала и будущие события: источник (чат, награда, панель) не знает, какие действия есть, действие не знает, откуда пришло. Причина: новая награда или новая реакция — строка в конфиге и запись в `REACTIONS`, без правки кода Twitch. Отвергнуто: отдельный обработчик под каждую награду.

### Баллы канала — в задаче 5, заготовки — в задаче 4
Задача 4 запрашивает право `channel:read:redemptions` при первом входе (иначе потом вход заново) и делает путь `act`. Сами награды — в задаче 5: та же подписка EventSub, что у сообщений. Кроме рандомайзера ручки такие: награда → действие, смена персонажа по тексту награды, переброс, персонажи «только за баллы» (флаг в `character.json`). Возврат баллов — нет в v1: Twitch даёт менять статус только наградам, созданным самой программой. Баллы есть только у компаньонов и партнёров — вопрос автору в `claude/open-questions.md`. В `claude/ideas.md` строка про реакции сужена до подписок и донатов, потому что баллы канала вошли в спеку.

### Админ-панель — страница программы в окне Edge, запуск крошечным exe
Спека «Админ-панель». Окно — `/admin` в Edge в режиме приложения: Edge есть в каждой Windows 11, окно выглядит как программа, код интерфейса — тот же, что у тестовой панели. Exe — запускатель на C#, собранный встроенным в Windows `csc.exe`: килобайты, без новых зависимостей. Отвергнуто: Electron — сотни МБ ради одного окна; Node SEA (~90 МБ) — запасной вариант; значок в трее — нужны нативные модули.

### Настройки из окна — в `data/settings.json` поверх `config.json`; «настройки через интерфейс» частично вошли в v1
В спеке v1 было «настроек через интерфейс нет»; по просьбе автора в окне — основные (лимит, рейд, облако, способы появления). `config.json` остаётся значениями по умолчанию в git; окно пишет `data/settings.json`. Причина: правки автора не появляются как изменения в git и не затираются обновлением программы. Пароль OBS — в `.env.local` (правило секретов в `CLAUDE.md`).

### OBS — через OBS WebSocket, встроенный в OBS 28+
Проверка связи, «добавить оверлей в сцену» (Browser Source с адресом и размером), «обновить оверлей» (сброс кэша — сейчас автор делает это руками в свойствах источника). Клиент на `ws` и `node:crypto`. Причина: «запуск — и всё готово в OBS» без ручной настройки источника. Отвергнуто: библиотека obs-websocket-js — лишняя зависимость ради пяти запросов.

### Задача 2 принята: в OBS работает, у автора заняла до 30 минут
Персонажи разные, шагают, смена видна сразу, после перезапуска те же. Факт — в таблице часов `claude/avatars-plan.md`.

### Поведение — таблицами, новое добавляется записью (требование автора при запуске задачи 3)
`public/js/actor.js`: `STATES` (состояние: анимация, запасная анимация, на земле ли, одноразовое ли, что делать каждый кадр), `ENTRANCES` (способы появления), `REACTIONS` (реакции поверх состояния). `public/js/render.js`: `EFFECTS` (эффекты без графики — облачко). Какую анимацию играть, решает логика (`actor.animation`), рисование только ищет её в листе; таблица «состояние → анимация» из `render.js` убрана. Причина: автор хочет расширять библиотеку действий и скинов без хардкода; новое поведение — одна запись, не правка `if`-цепочек. Отвергнуто: система плагинов (отдельные файлы поведений, загрузка по списку) — при нынешних 4 состояниях и 3 появлениях лишний код; таблицу можно разнести по файлам потом, не меняя формат записей.

### Сверх семи обязательных анимаций — необязательные, с запасной
Семь обязательных остались (на них держится поведение v1). Новые анимации необязательны: у состояния есть `fallback`, персонаж без новой анимации играет запасную. Битая необязательная анимация пропускается с сообщением, персонаж не выпадает из каталога (`src/characters.js`). Причина: новое поведение не должно ломать старых персонажей и требовать перерисовки всего каталога.

### «Один раз или по кругу» — в `character.json` (`"loop": false`), а не в коде
Заглушка «все анимации по кругу» закрыта: `jump`, `land`, `shake` у заглушек помечены `"loop": false` и держат последний кадр. Без поля — по кругу. Приземление и отряхивание длятся одно проигрывание своей анимации (длину логика берёт из листа персонажа). Причина: это свойство анимации, художник решает его вместе с кадрами; список одноразовых в коде — тот самый хардкод. Отвергнуто: вывод из имени анимации.

### Способ появления выбирает программа, по весам из `config.json`
`src/viewers.js` выбирает (`entrances` — веса, в окне после рейда — `parachute`), оверлей исполняет; незнакомое оверлею имя — «пух». Способ пишется в терминал (`[join] … з'яўленне: …`). Причина: окно после рейда знает только программа; веса правятся без кода; лог — проверка без браузера. При восстановлении списка (перезагрузка оверлея) способа нет — персонаж просто стоит на месте. Отвергнуто: выбор в оверлее — не знает про рейд, и две вкладки оверлея выбрали бы разное.

### Прыжок — реакция поверх состояния
Идущий продолжает идти в прыжке, стоящий — стоять; анимация `jump` на время прыжка. Прыгает только стоящий на земле (не в падении, не в облачке, не уходящий); второе сообщение во время прыжка не перезапускает его. Причина: спека «подпрыгивает и продолжает»; перезапуск на каждом сообщении при спаме — дрожание. Уход во время падения или облачка откладывается до приземления, чтобы персонаж не уходил по воздуху.

### Рейдеры в лимит зрителей не входят; новый рейд уводит прошлых
Рейдеры — отдельно от `maxOnScreen`, своя граница `raid.maxCount`. Приходят как обычные `join` с `raider: true`, уходят обычным `leave` по таймеру программы — оверлей про рейд не знает. Причина: рейд — короткое главное событие, его нельзя урезать из-за полного экрана; а вытеснять настоящих зрителей в очередь безымянными — хуже. Отвергнуто: рейдеры в лимите (вытесняют зрителей); рейдеры только на свободные места (при полном экране рейда не видно). Потолок на экране — `maxOnScreen` + `raid.maxCount`; второй рейд, пока гуляет первый, уводит первых — рейдеров не больше `raid.maxCount`. Рейдеры не пишутся в `data/viewers.json`, дизайн — случайный из каталога.

### Очередь — на программе, оверлей о ней не знает
`src/viewers.js`: не больше `maxOnScreen` на экране, лишние — в очереди по порядку прихода; ушёл с экрана — выходит первый из очереди (со своим способом появления); ушёл из очереди — просто убирается. Персонаж закрепляется уже при постановке в очередь, `!перс` меняет его и в очереди. Тестовая панель показывает экран, очередь и рейд отдельно. Заглушка «`maxOnScreen` не применяется» закрыта.

### Появление — три способа; заглушка «сразу на случайном месте» закрыта
Из-за края, облачко (рисуется программно пиксельными кругами), падение → приземление → отряхивание; на парашюте — спуск → приземление. Скорости, высоты, длительности — `overlay.*` в `config.json`, значения выбраны исполнителем, правятся после просмотра в OBS.

### Запуск в PowerShell — `npm.cmd start`, политику выполнения не трогаем
У автора PowerShell запрещает сценарии, `npm start` падает на `npm.ps1`. `npm.cmd` — тот же npm без сценария PowerShell, работает сразу. Отвергнуто: `Set-ExecutionPolicy` — меняет настройку безопасности Windows ради одной команды. Записано в `README.md` (раздел «Запуск»).

### Имена заглушек — без «і» и «ў»
Шесть заглушек: кухар, рыцар, маг, пастух, турыст, марак (`characters/`). Причина: имя набирают в `!перс`, а на русской раскладке, которая у многих зрителей, нет «і» и «ў». Имя сравнивается без учёта регистра и способа записи букв (Unicode NFC) — `src/characters.js`.
Отвергнуто: пірат, чараўнік, лыжнік, каўбой — эти буквы не набрать.

### Каталог читается один раз при запуске
Новая графика — перезапуск программы. Битый персонаж пропускается, причина — строкой па-беларуску в терминале. Проверяется всё, что может сломать рисование: семь обязательных анимаций, строки и кадры в пределах `sheet.png` (размер — из заголовка PNG).
Отвергнуто: слежение за папкой на лету — лишний код, графику меняют редко.

### Сервер отдаёт только `sheet.png` персонажей из каталога
Имя из адреса декодируется и ищется в каталоге; путь к файлу берётся из каталога, не из адреса. Причина: выйти за `characters/` нельзя по устройству, а не по проверке пути.

### Хранение — отдельный модуль `src/store.js`, запись синхронная через временный файл
Временный файл → fsync → переименование. Причина: при сбое остаётся целый старый или целый новый файл. Синхронно, потому что записей мало, а очередь асинхронных записей — лишняя сложность. Битый `viewers.json` не затирается: откладывается в `viewers.broken-<время>.json`, программа начинает с пустого списка и пишет об этом.

### «Реже всего используется» — по всем закреплённым в файле, не только по тем, кто на экране
Причина: так в спеке; иначе постоянные зрители, пришедшие вместе, чаще получали бы одинаковых.

### Смена персонажа работает и для зрителя не на экране
`Viewers.choose` (`src/viewers.js`) закрепляет выбор; на экране — событие `character`, спрайт меняется сразу. Причина: `!перс` могут написать раньше, чем зритель появится (список чата — раз в минуту). Неверное имя — событие `unknownCharacter`, сервер пишет в терминал имя и список доступных — тот же путь, что у остальных событий.

### Анимация — по состоянию логики, нет своей — `idle`
`public/js/render.js`: `idle` → `idle`, `walk` и `leave` → `walk`, остальные состояния — анимация с тем же именем. Кадр — от `actor.stateTime`, все анимации пока крутятся по кругу. У `actor.js` добавлено только поле `character`. Скорости (fps) заглушек выбраны исполнителем, правятся в `character.json`.

### Каркас задачи 1: логика персонажа отдельно от рисования
`public/js/actor.js` — состояния и движение, ничего не рисует; `public/js/render.js` — рисование; `public/js/overlay.js` — связывает их с WebSocket. У персонажа есть `facing` и `stateTime` — задел для зеркала и кадров анимации.
Причина: в задаче 2 меняется только `render.js`. Отвергнуто: один файл оверлея — спрайты пришлось бы вписывать в логику.

### Один вход для зрителей — `src/viewers.js`
Тестовая панель сейчас и Twitch потом вызывают одно и то же (`join`/`leave`/`message`), сервер пересылает события оверлею. id зрителя в тестах = ник в нижнем регистре, в задаче 4 станет user_id (заглушка в open-questions).
Причина: оверлей не должен знать, откуда пришёл зритель. Отвергнуто: отдельные пути для панели и Twitch.

### Один WebSocket на всех, при подключении — полный список
Оверлей и тестовая панель слушают одни события; при подключении программа шлёт `state` (настройки оверлея + текущие зрители), страницы сами переподключаются раз в 2 с. Так восстанавливается и перезагруженный оверлей, и оверлей после перезапуска программы.
Отвергнуто: HTTP-API для панели — второй канал для того же самого.

### Программа слушает только 127.0.0.1, WebSocket проверяет Origin
Причина: OBS на том же компьютере; программе незачем быть видной в сети, а без проверки Origin любой открытый сайт мог бы слать команды тестовой панели. Отвергнуто: доступ из сети (OBS на другом компьютере) — не нужен, вернуться при запросе.

### Значения по умолчанию, которых нет в спеке, выбраны исполнителем
Порт 4700, полоса, скорость, длина шага, паузы — в `config.json`, описание — в `README.md`. Причина: спека их не задаёт; правятся автором после просмотра в OBS без правки кода.

### Тексты тестовой панели и терминала — па-беларуску, комментарии в коде — по-русски
Причина: панель и сообщения программы — интерфейс продукта (правило языка в `CLAUDE.md`), комментарии — документация.

### `README.md` в корне переведён из UTF-16 в UTF-8
Причина: остальные файлы в UTF-8; смешение кодировок ломает кириллицу в редакторах и на GitHub. Заголовок сохранён.

### Заведено направление «аватары зрителей» (`claude/avatars-spec.md`, `claude/avatars-plan.md`)
Зачем: это сам продукт. Исходник — описание автора и черновое обсуждение с ChatGPT. Из обсуждения взяты требования автора, утверждения ИИ проверены отдельно.
Отвергнуто: готовый Stream Avatars (платный); Meld Pixel Art Chat Avatars (персонаж исчезает через ~5 мин без сообщений); варианты, где аватарка Twitch становится телом персонажа (автору не нравится). Готовые open-source проекты — только референсы.

### Присутствие = список чата Twitch, уход — после 3 пропущенных опросов
Причина: Twitch не отдаёт список зрителей, только залогиненных в чате (Get Chatters; проверено по dev.twitch.tv). IRC JOIN/PART тоже про чат и отключается при >1000 в чате. Запас в 3 опроса — список обновляется с задержкой.
Отвергнуто: «только написавшие в чат» (не будет молчунов). «Список + мгновенное появление по сообщению» автор не выбрал — вопрос в open-questions.

### Рейдеры — безымянные парашютисты
Причина: событие `channel.raid` содержит только канал-рейдер и число зрителей, ников нет (проверено по EventSub reference). Идея «собрать ники рейдеров» невыполнима.

### Персонаж выдаётся случайно, меняется командой `!перс`, хранится по user_id в JSON
Причина: выбор автора «случайно + смена». user_id, а не ник: ник можно сменить. JSON: зрителей мало, база данных не нужна.
Отвергнуто: только случайно (зритель не выбирает), только выбор (у большинства будет дефолтный), SQLite (избыточно для v1).

### Графика v1 — заглушки, формат спрайтов фиксируется сразу
Причина: механику можно проверить без готового арта. Фиксированный формат (`character.json` + `sheet.png`) позволяет заменить графику без правки кода. 32×32 — значение по умолчанию, меняется в `character.json`.

### Программа локальная (Node.js), оверлей — страница на localhost в OBS Browser Source
Причина: $0/мес, нет сервера, который нужно держать и защищать. Вход в Twitch — Device Code Flow: публичный клиент, client secret не нужен.
Отвергнуто: облачный сервис — деньги и сложность без выгоды для одного стримера.

### Токены Twitch — в `data/twitch-tokens.json`, не в `.env.local`
Причина: refresh token публичного клиента одноразовый, программа перезаписывает его при каждом обновлении; переписывать `.env.local` программой ненадёжно. `data/` в `.gitignore`. Client ID остаётся в `.env.local`.

### Объём v1: разные появления, рейд, реакция на сообщение
Вне v1: лазанье по аватарке, автобус при рейде, кастомизация — в `claude/ideas.md`. Причина: выбор автора.

### Оценка ChatGPT в «сессиях Codex и токенах» не перенесена

### Заведена система работы с Claude
Документация живёт в папке проекта (git), в проекте claude.ai — только правила (`claude/project-instructions.md`). Правила для Claude Code — `CLAUDE.md`, карта и правила ведения — `claude/README.md`.
Причина: решения, принятые в чатах, теряются вместе с чатами; два комплекта документов (в claude.ai и в папке) на прошлом проекте разошлись.
Система перенесена с проекта сайта, где проработала месяц.

### Работа идёт цепочкой чатов, профильного чата нет
Один чат — одна задача; закрывающий чат пишет журнал и промпт следующей задачи. Планировочный чат в claude.ai — только для нового направления или крупного разбора.
Причина: приоритет — экономия токенов; длинный чат оплачивает всю переписку в каждом запросе.
Отвергнуто: постоянный диспетчерский чат на каждую задачу (лишняя пара чатов на каждый шаг) и профильный чат (нет области со своим хозяином). Вернуться, если появится такая область — например, дизайн аватаров.

### Экономия токенов — без вреда результату
Правила экономии в `CLAUDE.md`. Не экономится: перечитывание файла перед записью, проверка сборки и `git show --stat`.
Причина: на сайте запись из старой копии трижды молча затирала чужие правки — это дороже любых сэкономленных токенов.
