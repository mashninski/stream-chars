# stream-chars

Аватары зрителей для стримов на Twitch через OBS: по нижней полосе экрана ходят персонажи с никами зрителей.

## Запуск
Нужен Node.js 20 или новее (`node -v`).

```
npm install
npm start
```

`npm install` — один раз (и после изменения `package.json`). `npm start` запускает программу; остановить — `Ctrl+C` в том же окне.

В PowerShell (синее или чёрное окно «Windows PowerShell») пишите `npm.cmd start` и `npm.cmd install`: просто `npm` там блокируется ошибкой «выполнение сценариев отключено в этой системе». В «Командной строке» (cmd) работает и `npm start`.

## Адреса
- `http://localhost:4700/overlay` — оверлей для OBS: Browser Source, 1920×1080.
- `http://localhost:4700/test` — тестовая панель: добавить/убрать зрителя без Twitch.

Порт и остальные настройки — `config.json`.

## Настройки (`config.json`)
- `port` — порт программы.
- `maxOnScreen` — сколько персонажей зрителей одновременно на экране. Остальные ждут в очереди и выходят по порядку, когда кто-то уходит. Рейдеры сюда не входят.
- `entrances` — способы появления и как часто каждый выпадает: `edge` — выходит из-за края, `poof` — облачко, `fall` — падает сверху. Число — вес: `{ "edge": 2, "poof": 1, "fall": 1 }` — из-за края вдвое чаще. `0` или убрать строку — способ не выпадает.
- `triggers` — какое действие у какого источника: `message` — сообщение в чате (сейчас — кнопка «Паведамленне» тестовой панели). Значение — имя реакции (`jump` — прыжок) или сцены. Облако с текстом сообщения показывается всегда, кроме команд (начинаются с `!`).
- `bubble` — облако с сообщением: `maxChars` — сколько символов показать (длиннее — обрезается по слову с «…»), `maxWidth` — ширина облака, px, `maxLines` — строк не больше, `fontSize` — размер шрифта, px; висит `minSeconds` + `secondsPerChar` × длина текста, но не дольше `maxSeconds`, с. Новое сообщение того же зрителя заменяет облако.
- `raid.maxCount` — сколько парашютистов спускается при рейде, не больше.
- `raid.staySeconds` — сколько секунд рейдеры гуляют, потом уходят.
- `raid.parachuteWindowSeconds` — сколько секунд после рейда новые зрители появляются на парашюте.
- `overlay.width`, `overlay.height` — размер оверлея.
- `overlay.strip` — полоса, по которой ходят: `left`/`right` — границы по горизонтали, `groundY` — линия земли (px сверху).
- `overlay.scale` — во сколько раз увеличен пиксель арта.
- `overlay.walkSpeed` — скорость ходьбы, px/с.
- `overlay.walkDistance` — случайная длина шага, [от, до] px.
- `overlay.idlePause` — случайная пауза стояния, [от, до] с.
- `overlay.jumpHeight`, `overlay.jumpTime` — высота прыжка на сообщение (px) и его длительность (с).
- `overlay.fallGravity` — ускорение падения, px/с².
- `overlay.parachuteSpeed` — скорость спуска на парашюте, px/с.
- `overlay.parachuteSpread` — разброс стартовой высоты парашютистов, px: чем больше, тем дольше приземляется вся толпа рейда.
- `overlay.poofTime` — длительность облачка, с.

## Свои персонажи
Каждый персонаж — папка в `characters/`. Имя папки — имя персонажа: его зритель пишет в `!перс <імя>`. Без пробелов; лучше без «і» и «ў» — их нет на русской раскладке. Большие и маленькие буквы не различаются.

В папке два файла:
- `sheet.png` — лист кадров. Одна анимация — одна строка, кадры идут слева направо без промежутков. Все кадры смотрят **вправо** (влево программа отражает сама). Низ кадра — земля, ноги ставьте на нижний ряд пикселей. Фон прозрачный.
- `character.json` — описание листа:

```json
{
  "frameWidth": 32,
  "frameHeight": 32,
  "animations": {
    "idle":      { "row": 0, "frames": 2, "fps": 2 },
    "walk":      { "row": 1, "frames": 4, "fps": 8 },
    "jump":      { "row": 2, "frames": 2, "fps": 8,  "loop": false },
    "fall":      { "row": 3, "frames": 2, "fps": 8 },
    "land":      { "row": 4, "frames": 2, "fps": 10, "loop": false },
    "shake":     { "row": 5, "frames": 4, "fps": 16, "loop": false },
    "parachute": { "row": 6, "frames": 2, "fps": 3 }
  }
}
```

`frameWidth`, `frameHeight` — размер кадра в пикселях. У анимации: `row` — номер строки (сверху, счёт с 0), `frames` — сколько кадров, `fps` — кадров в секунду, `loop` — `false`: проиграть один раз и остановиться на последнем кадре (без `loop` — по кругу). Приземление и отряхивание длятся ровно одно проигрывание своей анимации. Можно добавить свои анимации сверх семи — ими пользуется новое поведение (см. «Новое поведение»). Все семь анимаций обязательны: стоит, идёт, прыжок, падение, приземление, встряхивается, парашют. Увеличение на экране — `overlay.scale` в `config.json`, пиксели остаются чёткими.

Заменить заглушку: положите свои `sheet.png` и `character.json` в её папку или заведите новую папку и удалите ненужную. Код править не надо — перезапустите программу. В терминале будет список загруженных персонажей; с ошибкой в файлах персонаж пропускается, и написано почему. Зрителям, чей персонаж исчез, программа выдаст нового.

Заглушки рисует `npm run stubs` (`scripts/make-stubs.js`): перезаписывает только папки шести заглушек.

## Новое поведение
Поведение собрано в таблицы — новое добавляется записью, остальной код не трогается:
- `public/js/actor.js` → `STATES` — состояние (что делает и какую анимацию играет), `ENTRANCES` — способ появления, `REACTIONS` — реакция поверх того, что персонаж делает (как прыжок на сообщение).
- Новый способ появления — запись в `ENTRANCES` и строка в `entrances` в `config.json`.
- Новая анимация — строка в `sheet.png` и запись в `character.json` у персонажей. У состояния можно указать запасную анимацию (`fallback`): персонажи без новой анимации играют её.
- Эффект без графики (как облачко) — запись в `EFFECTS` в `public/js/render.js`.

## Для разработки
Программу можно запустить с другой папкой данных и другим портом — настоящие `data/` и порт не трогаются:

```
node src/server.js --data-dir D:\temp\sc-data --port 4710
```

То же переменными окружения: `STREAM_CHARS_DATA_DIR`, `STREAM_CHARS_PORT` (аргумент важнее).

- `--parent-pid <число>` — программа сама выходит, когда процесса с этим номером больше нет (проверка раз в 5 с). Так скрипт OBS останавливает её вместе с OBS.
- Файл `stop` в папке данных — сигнал «выйти» (проверка раз в секунду; файл удаляется).
- Второй запуск на занятом порту — строка в журнал и тихий выход (код 0).
- Журнал: терминал, файл `<папка данных>/logs/<дата>.log` (хранятся 7 последних), последние 500 строк — в админке.
- Настройки: `config.json` — значения по умолчанию (в git, программа его не меняет); `<папка данных>/settings.json` — только изменённое из админки, поверх. Неверное значение админка не сохраняет и пишет, что не так; неверная строка в `settings.json` при запуске пропускается со строкой в журнале. Всё, кроме порта, применяется без перезапуска.
