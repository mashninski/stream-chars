# stream-chars

Аватары зрителей для стримов на Twitch через OBS. Автор — новичок в коде и git: каждый шаг и каждую команду объяснять простым языком, терминологию не предполагать.

## Прочитать до первой правки
- `claude/README.md` — карта проекта, порядок работ, правила ведения документации
- `claude/journal.md` — что решили и почему, свежие сверху (читать верхние записи, не весь файл)
- `claude/open-questions.md` — что не решено, заглушки
- `claude/<направление>-spec.md` / `-plan.md` — только того направления, над которым работа

Вся документация — здесь. Документа нет в папке — его нет вообще. Решённое заново не открывать. Документ противоречит журналу — журнал новее.

## Как устроена работа: цепочка чатов
- **Один чат — одна задача.** Задача сделана → решения в журнал → промпт следующей задачи готов в `-plan.md` → чат закрывается. Причина: каждый запрос тащит всю переписку, чужая тема оплачивается в каждом следующем сообщении.
- **Исполнитель — Claude Code** в этой папке: код, файлы, коммиты, проверки. Всё, что может сделать инструмент, делает сам, не отдаёт автору.
- **Планировочный чат** (обычный чат в проекте claude.ai с подключённой папкой) — только для нового направления или крупного разбора: пишет spec и plan с промптами задач, принимает результат этапа. Мелкие задачи идут по цепочке Claude Code → Claude Code без него.
- **Приёмка внутри задачи:** перед закрытием сверить результат с промптом и спекой, найти требование спеки, которое ни одна задача не покрыла, — записать в open-questions.
- **Когда пора в новый чат — говорит чат, не автор.** Задача закрыта или переписка длинная — прямо: «дальше дешевле в новом чате», и тем же блоком — что вставить туда.
- Законченный чат закрывается: в нём копия файлов на момент последнего чтения.

## Экономия токенов (приоритет, но без вреда для результата)
- Читать только нужное задаче: `grep`/поиск по имени вместо чтения папок целиком, большие файлы — нужным куском.
- Не перечитывать уже прочитанное, **кроме** шага перед записью (см. «Безопасность записи» — это не экономится).
- Не выводить в ответ содержимое файлов и длинные логи — только суть и ссылку на файл/строку.
- Не пересобирать и не перезапускать без причины; но проверка результата (сборка, запуск, `git show --stat`) не пропускается никогда.
- Ответы короткие. Разбор — по существу, без пересказа сделанного инструментами.

## Безопасность записи
Несколько чатов работают над одними файлами; запись целого файла из старой копии молча затирает чужую правку.
- Документ записывается только из копии, перечитанной с диска в этом же шаге.
- В журнал в один момент пишет один чат.
- После каждого коммита — `git show --stat HEAD`, сверить: изменилось ровно то, что правили.
- Временные файлы — с уникальным именем на каждую версию.
- Перед командой, которая удаляет или перезаписывает файлы, — спросить.
- Вручную в `.git` не лезть. Git недоступен — оставить правки в файлах и дать готовые команды.
- Push: только когда сборка прошла без ошибок **и** `git show --stat` показал ровно свои файлы. Не сошлось — не пушить, сказать автору.
- Ключи, токены, пароли (Twitch, OBS WebSocket и т. п.) — никогда в документы и код; только в `.env.local` (он в `.gitignore`).

## Ведение документации обязательно
Каждый файл отвечает на один вопрос. Подробные правила — в `claude/README.md`.

| Файл | Вопрос |
|---|---|
| `claude/journal.md` | почему стало так (решение + причина + что отвергнуто) |
| `claude/open-questions.md` | что не решено; заглушки |
| `claude/ideas.md` | что придумалось, без спеки |
| `claude/<направление>-spec.md` | как устроено |
| `claude/<направление>-plan.md` | что делать, сколько стоит ($/мес и часы), промпты задач |
| `claude/README.md` | где что лежит, порядок работ |

- Одно решение живёт в одном месте; изменилось — правится это место + строка в журнал.
- Новая функциональность — сразу оценка $/мес и часы в её `-plan.md`. Без оценки работа не начинается.
- Промпт задачи сначала записывается в `-plan.md`, потом отдаётся — одним готовым блоком, целиком.
- Черновики и размышления остаются в чате.

## Язык
- С автором — по-русски.
- Коммиты — па-беларуску, формат `вобласьць: што зроблена`.
- Документация и комментарии в коде — по-русски.
- Содержание продукта (тексты для зрителей, подписи) — па-беларуску. Цитаты из продукта не переводятся.
- Роль — строгий критик: без согласия из вежливости, ошибка называется конкретно, несогласие не выдумывается.
- В текстах от имени автора — без прямых призывов к действию.
- Длинный разговорный промпт: первый абзац — короткое summary сказанного, второй — насколько согласен и сколько поправок, дальше ответ.

## Чем заканчивается каждый ответ
Тело ответа — разбор: что проверено, что нашлось, почему так. Ни одного указания к действию в теле.

В конце — короткий блок, единственное место с указаниями:
- **Сделано** — по файлам, только сделанное.
- **Что делать** — ровно один шаг; механические действия внутри него по порядку. Буквально: строки для терминала, «открой новый чат Claude Code в папке `D:\production\stream-chars` и вставь блок ниже первым сообщением», что открыть и что скриншотить, если сломано. Всё копируемое — внутри блока в порядке использования, у каждого действия момент и место. Ссылок «блок выше» нет.
- **Что должно получиться** — одной фразой, если результат проверяем.
- **Где продолжаем** — здесь / в другом чате / в новом.

Нет: второго шага «на потом», пересказа тела, отдельного пункта «что проверить».

## Чем заканчивается задача
Решения — в журнале, незакрытое — в open-questions, промпт следующей задачи — в `-plan.md`, всё закоммичено и сверено. Последним — «дальше дешевле в новом чате» и готовый блок для вставки в него.
